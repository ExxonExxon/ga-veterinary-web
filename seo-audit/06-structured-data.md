# 06 — Structured Data

### Summary
Schema is minimal and auto-generated by Yoast. Every page emits the same generic set — `WebSite`, `WebPage` (with `CollectionPage` on archives), `BreadcrumbList`, and the Yoast `SearchAction`/`EntryPoint`/`ListItem`/`PropertyValueSpecification` block for the site-search box. There is **no Product, no LocalBusiness, no Organization, no Article, and no FAQPage** schema anywhere. The single biggest structured-data opportunity for a custom-manufacturer is completely missed.

### Issues Found

| Issue | Severity (Critical/High/Medium/Low) | Affected URLs (sample) | Fix |
|---|---|---|---|
| **No `Product` schema on product pages** — `/craniotomyhook/`, `/bone-lever/`, `/retractor/`, `/needles/`, `/kocher-forceps/` sell physical instruments but have no Product/Offer markup (no name, image, description, SKU, price, availability). | **Critical** | `/craniotomyhook/`, `/bone-lever/`, `/retractor/`, `/needles/`, `/kocher-forceps/` | Add `Product` (or `IndividualProduct`) schema with `name`, `image`, `description`, `material`, `brand: {Organization}`, and offer/availability. |
| **No `Organization` schema** — the `WebSite` publisher isn't represented as an Organization, so brand/entity signals (logo, sameAs, contactPoint, address) are missing. | High | `/` (all) | Add Organization schema with `@id` matching the WebSite, `logo`, `url`, `sameAs` (FB/LinkedIn), `contactPoint`, and address/geo. |
| **No `LocalBusiness` / `MedicalBusiness` schema** — critical for a business that wants local discovery (see 09). Even a P.O.-Box manufacturer should declare address, phone, geo, and hours. | High | `/contact/` (site-wide) | Add `LocalBusiness`/`MedicalBusiness` with NAP, geo, sameAs; only if the address is legitimately published for the business. |
| **No FAQPage schema** — `/faq/` renders real Q&A content but not as structured data. | Medium | `/faq/` | Mark up the FAQ as `FAQPage` (questions/answers mirroring visible text). |
| **No `Article` schema on content pages** — `/about/`, `/faq/`, `/custom-instruments/` have no article/author markup, so no `author`/`datePublished`/`dateModified` entmentity signal (amplifies the E-E-A-T gap in 04). | Medium | `/about/`, `/faq/`, `/custom-instruments/` | Use `Article`/`WebPage` with `author` (Person), `datePublished`, `dateModified`. |
| **`BreadcrumbList` is present but includes the full page title as the last item** on some templates (e.g. `/portfolio-types/applications/` shows the title as breadcrumb), and breadcrumbs reference the auto-title rather than a clean entity name. | Low | `/portfolio-types/*`, `/portfolio-item/*` | Keep breadcrumbs but set clean name values (e.g. "Applications", not "Applications Archives - GA Medical Pty Ltd"). |
| **ImageObject / SearchAction schema consistency**: `SearchAction` targets the site search box; ensure the search results page is `noindex` (search results not observed/indexed — confirm Yoast search pages are noindexed). | Low | n/a | Verify `/search/...` is `noindex,noarchive` in Yoast; not observed in site inspection but should be confirmed. |

### Not Assessed
- **Schema validation against schema.org validators** (Rich Results Test) was done by manual spec review, not automated validator output (no validator access). Checks for required properties were by spec.
- **Any schema not matching visible content**: aside from the empty-H1 homepage and the broken-Google-Maps block, no schema was found that obviously mismatches visible content — the bigger risk is the *absence* of the schema types that should be there.
